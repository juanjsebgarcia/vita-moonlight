# Morpheus

The new theme, drawn natively with vita2d. The look, the tokens and every
screen's layout come from the design guide (`DESIGN.md`, kept with the
theme's design work); this file is the primitives' manual for whoever builds
the screens.

| File | What |
|---|---|
| `mph.h` | The whole API: tokens, frame, shapes, textures, text, motion, chrome, rows, lists, controls |
| `mph_draw.c` | Frame, time, the batch, the transform, clipping, shapes, background, icons, covers, hatch |
| `mph_text.c` | The type ramp: our own FreeType glyph cache, rich text, ellipsis, wrapping, upper case |
| `mph_anim.c` | Easing curves (64-entry tables), tweens, followers, springs |
| `mph_chrome.c` | Status bar, legend, category labels, separators, scroll bar |

| `mph_perf.c` | The developer HUD |
| `mph_icons.h` | The icon atlas's rectangles, generated by `tools/morpheus/atlas.js` |
| `morpheus.c` | The theme's entry points: the dispatch to the screens below, a plain list fallback, and the gallery |
| `mph_screens.h` | Every screen's entry points, and the dispatch convention |

## How a screen draws

Every theme entry point that draws brackets its drawing:

```c
mph_frame_begin();               // samples the time, resets the batch
mph_bg_draw();                   // background, 1 draw
mph_statusbar(title);
...                              // shapes, then icons, then text
mph_frame_end(config.developer_mode);   // flushes; draws the HUD in developer mode
```

### Dispatch

`morpheus.c` is a thin dispatcher. `mph_draw_menu()` starts the frame, notes
which screen is on show, and switches on `view->screen->id` to the screen's
draw function; `mph_menu_follow()` switches the same way to its follow
function. Every menu screen is such a pair, declared in `mph_screens.h`:

```c
void mph_screen_<name>_draw(const menu_view *view, const mph_enter *enter);
void mph_screen_<name>_follow(menu_view *view);
```

- **draw** runs between `mph_frame_begin()` and `mph_frame_end()`, which the
  dispatcher calls (and it resets the transform after). It draws the whole
  screen: background, status bar, content, legend (`mph_menu_legend(view)`).
- **enter** is the screen's enter transition: `enter->t0` is when the screen
  came on, `enter->animate` whether it slides in (it doesn't on a return to
  the screen before). `mph_enter_apply(enter)` applies the fade and the
  18 px slide to what follows; `mph_enter_k(enter)` gives the progress for a
  screen that mixes it into its own opacities. `mph_enter_is_new(enter,
  &seen)` tells when the screen's own state (lists, focus, tweens) should
  start afresh. The status bar and the legend stay put.
- **follow** stores in `view->scroll` the scroll that keeps the selected row
  in view, measured with the same layout as draw, so a parent screen comes
  back where it was.

A screen without a case gets a plain list (every screen has one today).
Dialogs and overlays are the theme struct's own entries and bracket their
own frames. A new screen goes in a new `mph_screen_<name>.c`, with its pair
in `mph_screens.h` and a case in both switches.

## Conventions

- **Coordinates** are device pixels on 960x544, as floats. Rects are
  `mph_rect {x, y, w, h}`. Shapes on whole pixels have crisp straight edges;
  curves get a 1 px antialiasing fringe.
- **Colours** are vita2d `RGBA8` (`0xAABBGGRR`). Use the `MPH_C_*` tokens;
  `mph_alpha(c, a)` scales alpha and `mph_mix(a, b, t)` blends.
  Some tokens depart from the demo for legibility (DESIGN.md §0): `FAINT`
  is .55 (about #8A8F99, 5.6:1) and `DIM` .75; `SURFACE` panels carry a
  1 px `FAINT` outline (`mph_surface()`); keycaps are 12 px; host status
  marks are 10 px across (`mph_status_mark()`).
- **Text** is drawn at a baseline. `mph_baseline(type, top, h)` centres one
  line in a box. Only the 18 styles of `mph_type` exist; each returns its
  advance. Text may hold button markers (`{confirm}`, `{triangle}`, `{l}`,
  `{left}`...): face buttons draw as a disc and a coloured stroke, the D-pad,
  sticks and touch pads as icons in the text's colour, and L, R, START and the
  other labelled buttons as keycaps. Characters the fonts lack (Japanese,
  Korean, Chinese) come from `text_system_font()`, in the forms the UI
  language uses.
- **Upper case** labels (categories, kickers): pass `mph_upper(s)` (cached).
- **Wrapping:** `mph_wrap()` every frame is fine: it's a cache lookup after
  the first time. Lines stay valid for 31 more wraps.
- **Motion** is by time, never by frames: `mph_time()`, `mph_dt()`, tweens
  (`mph_tween_to` retargets from the current value, like a CSS transition),
  `mph_follow` (exponential, frame-rate independent) and springs. The curves
  are `MPH_EASE_FOCUS` (overshoot), `_OUT`, `_CSS` and `_LINEAR`; durations are
  the `MPH_M_*` tokens.
- **Focus:** `mph_focus_set(&f, rect, radius, MPH_FOCUS_PILL or _RING, key)`
  each frame, then `mph_focus_draw(&f, dx, dy)` under the item. A new key
  glides over 300 ms; the first appearance fades in.
- **Lists:** keep an `mph_list_state` per list, `mph_list_reset()` it when
  the screen changes, and call `mph_list(view, rows, n, focused, target,
  &state, track_x)`. `mph_list_target()` gives the scroll that keeps the
  focused row in view; `menu_follow` stores it in `view->scroll` so a parent
  screen comes back where it was. Rows come from `mph_row_from_entry()` (or
  `mph_rows_from_entries()` for a run). Layouts of their own use
  `mph_scroll_keep()` for the same rule over their items. A row's value and
  suffix take what its label leaves; when they don't fit, the value is cut
  first (to 64 px at least), then the label.
- **Enter and modal transitions:** `mph_transform(alpha, scale, cx, cy, dx,
  dy)` applies to everything drawn after it (shapes, icons, text) until
  `mph_transform_reset()`. Menu screens slide content in over
  `MPH_M_ENTER` with `mph_enter_apply()` when the screen id changes (not when
  returning to the previous one); dialogs scale in over `MPH_M_MODAL`.
- **Clipping:** `mph_clip(rect)` ... `mph_clip_end()`: one stencil pass. Lists
  clip only when their rows overflow.

## How the batch works, and the speed rules

Shapes are triangles with a colour per vertex, written straight into vita2d's
frame pool: every shape drawn in a row is **one** draw call. Text, icons and
covers are textured quads that collect in runs by (texture, tint), and each
run is one draw call. A shape flushes the pending textured runs first, and a
textured quad flushes pending shapes, so painter's order holds between shapes
and what's on them. Between two shapes, all the text of one colour on the
screen is a single draw.

Text no longer goes through vita2d's fonts: `mph_text.c` rasterises with
FreeType (light hinting, unhinted advances, float pen) into one 1024x512
atlas keyed by (style, character), so each style has crisp glyphs at its own
size, measuring is a table walk that never draws, and a full atlas starts
over at the next frame instead of dropping glyphs.

1. Never call `vita2d_draw_*` from a screen. If you must, call `mph_flush()`
   first.
2. Draw each layer as **shapes, then icons, then text**. Interleaving costs a
   draw call per switch. `mph_list` draws all rows' shapes, then all their
   icons and text.
3. Textured runs draw in the order they were first used since the last
   shape. If one textured thing must cover another of a different texture or
   colour (text over a cover), put a shape between them or `mph_flush()`.
4. Use only the type ramp. Don't invent sizes.
5. Nothing allocates per frame: no `malloc`, no textures, no file reads.
   Format strings into static buffers when their data changes (the status
   bar's clock does once a minute).
6. Skip what's off screen; one clip per list at most.
7. Shadows only where the guide lists them (`mph_shadow`): they are the most
   vertices on a screen (about 1,000 each).
8. Stream overlays run on the video thread every frame: no shadows, nothing
   wider than a 1 px fringe, measurements cached by `stats_view.version`.
9. Report the HUD's numbers for each screen you build.

## The developer HUD and the gallery

With `developer_mode = true` the bottom left shows `cpu avg/max µs`, the frame
interval, draws, vertices, glyphs and pool use (current and the second's
peak). The HUD is drawn after the frame is measured.

The developer screen request (`ux0:data/moonlight/screen.req`) takes a
`morpheus` prefix that switches to this theme before opening the screen, so
dialogs and overlays can be checked here too: `morpheus flash <text>`,
`morpheus help <title>|<text>`, or `morpheus` alone to open the host list in
Morpheus. `morpheus help mph:gallery|` opens the gallery: every primitive on
one screen.
